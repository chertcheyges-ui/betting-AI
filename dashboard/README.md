# Тестовая версия панели

Два независимых раздела:

- Обзор данных: импорт JSON из export_match_report.py, поиск, фильтры, карточки команд и полнота полей.
- Учебная лаборатория: повторяемые синтетические наблюдения с известными исходами, accuracy, multiclass Brier score и log loss. Это не оценка обученной модели проекта.

## Пользовательская проверка

1. Откройте index.html через локальный HTTP-сервер или опубликованный сайт. Последний опубликованный снимок реальных матчей откроется автоматически.
2. Проверьте дату сбора, найдите команду, выберите «Со статистикой игры» и откройте карточку.
3. Откройте «Учебная лаборатория». У каждого учебного матча видны вымышленные клубы, вероятности и известный результат.
4. Смените уверенность и пересчитайте. Accuracy останется прежней при одинаковом размере выборки, вероятностные ошибки изменятся.
5. Скачайте набор, перезагрузите страницу, загрузите скачанный файл и сравните результаты.
6. Попробуйте JSON с неверной суммой вероятностей: появится ошибка, предыдущий набор останется доступен.
7. Проверьте те же действия на телефоне.

Учебный эксперимент и настройки сохраняются только в localStorage браузера. Загруженные пользователем отчёты обзора данных остаются в памяти вкладки. Последний общий снимок хранится в dist/latest-report.json и загружается при открытии страницы. Ключ API на сайт не передаётся. Автоматического фонового получения матчей и прямой трансляции счёта нет.

## Локальный запуск

Из папки dashboard: python3 -m http.server 8765 --bind 127.0.0.1 --directory dist

Открыть http://127.0.0.1:8765/.

Из корня Python-проекта: .venv/bin/python export_match_report.py

Загрузить reports/match-report.json через кнопку обзора данных. Статусы degraded и error означают неполный сбор или ошибку. Пустой список может быть корректным результатом отбора матчей.

### Реальные расписание, результаты и статистика

.venv/bin/python export_fixture_snapshot.py

Скрипт записывает dashboard/dist/latest-report.json. Дата по умолчанию — текущая дата Минска; можно передать --date YYYY-MM-DD. По умолчанию в снимке 16 матчей, приоритет — крупные лиги. Для трёх начавшихся/завершённых матчей запрашивается статистика игры. Промежуток между запросами не менее 7,5 секунды. Опции --max-fixtures 1–100 и --statistics 0–5 ограничивают объём. При ошибке списка матчей старый снимок не перезаписывается.

Кнопка «Открыть последний снимок» перечитывает опубликованный JSON без обращения к API. Новый локальный снимок можно загрузить вручную; обновление снимка на общем сайте требует публикации. Неизвестные значения и счёт не начавшихся матчей сохраняются как null, а не как нули. Статистика формы не выводится из статистики одной игры.

## Проверки

node evaluation.test.cjs

Формулы: средняя сумма квадратов по трём классам (Brier 0–2, без деления на 3), среднее −ln(p фактического класса), accuracy по argmax с выбором первого класса при равенстве. Нулевая вероятность известного результата даёт бесконечный log loss; на странице отображается ∞.

Статистическая точность локальной модели на реальных матчах ещё не подтверждена. Для такой оценки нужна независимая выборка без утечки данных.
